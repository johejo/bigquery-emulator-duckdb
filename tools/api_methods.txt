# The REST API requests //:api_probe sends, which generate docs/api.md. The methods themselves come
# from third_party/bigquery/discovery.json; a method without requests here is probed with one the
# probe builds from its path.
#
#   file NAME | LINE          Writes LINE to the file NAME in the probe's scratch directory, $DIR.
#   setup METHOD PATH [BODY]  A request sent to every fresh emulator before a probe.
#   request ID | METHOD PATH [BODY]
#                             A request for the method ID, such as bigquery.jobs.query. Repeat it
#                             to probe several forms of one method.
#   note ID | TEXT            What the emulator ignores or does differently from BigQuery.
#
# Paths are below the server root and may carry a query string. Every request here must succeed
# or be rejected as unsupported; the probe fails on one that fails for another reason.

note bigquery.tables.insert | Keeps `tableReference`, `schema` and GoogleSQL view definitions; partitioning, clustering, labels and descriptions are ignored.
request bigquery.tables.patch | PATCH /bigquery/v2/projects/test/datasets/d/tables/t {"schema": {"fields": [{"name": "id", "type": "INTEGER", "description": "key"}, {"name": "name", "type": "STRING"}]}}
request bigquery.tables.patch | PATCH /bigquery/v2/projects/test/datasets/d/tables/w {"view": {"query": "SELECT 2 AS id"}}
note bigquery.tables.patch | Changes `schema` and view definitions only, ignoring other fields such as `description`, `labels` and `expirationTime`. A schema may add NULLABLE and REPEATED fields after the existing ones, records included, relax REQUIRED to NULLABLE and change descriptions; existing fields keep their order. Changing a view's schema is not supported. Ignores `autodetect_schema` and the etag.
request bigquery.tables.update | PUT /bigquery/v2/projects/test/datasets/d/tables/t {"tableReference": {"tableId": "t"}, "schema": {"fields": [{"name": "id", "type": "INTEGER"}, {"name": "name", "type": "STRING"}]}}
request bigquery.tables.update | PUT /bigquery/v2/projects/test/datasets/d/tables/w {"view": {"query": "SELECT 2 AS id", "useLegacySql": false}}
note bigquery.tables.update | Behaves like `tables.patch`: fields the request leaves out, including `schema`, are kept rather than cleared.
